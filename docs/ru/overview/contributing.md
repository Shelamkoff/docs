# Обзор — Руководство по участию в разработке

Хотите помочь развитию Spiral? Это проект с открытым исходным кодом, которому необходим вклад разработчиков, чтобы
продолжать развиваться и становиться лучше. Принять участие можно разными способами.

## Pull request

Один из способов внести вклад во фреймворк — отправить pull request на GitHub.
Если у вас есть исправление или улучшение, создайте [pull request](https://github.com/spiral/framework/pulls), после чего
его рассмотрят сопровождающие проекта. При подготовке pull request необходимо соблюдать несколько требований.

### Объявляйте строгую типизацию

Во всех PHP-файлах фреймворка необходимо включать
[строгую типизацию](https://www.php.net/manual/en/language.types.declarations.php#language.types.declarations.strict)
с помощью директивы `declare(strict_types=1);` в начале файла. Это помогает обеспечить типобезопасность кода и снижает
риск ошибок.

Пример использования директивы:

```php
<?php

declare(strict_types=1);

namespace App;

// ...
```

### Соблюдайте стандарт кодирования PSR-12

Убедитесь, что ваш код соответствует стандарту кодирования
[PSR-12](https://www.php-fig.org/psr/psr-12/). Он определяет правила форматирования и структуры кода, благодаря которым
кодовая база остаётся единообразной и удобной для чтения.

#### Проверка кода

```terminal
./vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php -vvv --dry-run --using-cache=no
```

#### Автоматическое исправление стиля кода

```terminal
./vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php -vvv --using-cache=no
```

> **Примечание**
> Пакет принудительно использует окончания строк `CL`.

### Добавляйте тесты

При отправке изменений в Spiral важно добавлять тесты. Они подтверждают, что предложенный код работает должным образом,
не создаёт новых проблем и упрощает сопровождающим проверку корректности изменений.

#### Запуск тестов

```terminal
./vendor/bin/phpunit
```

### Используйте Psalm

Перед отправкой кода необходимо проверить его с помощью [Psalm](https://psalm.dev/). Этот анализатор помогает находить
ошибки и проверяет соответствие принятым практикам. При проверке кода Spiral используется уровень ошибок Psalm **4**.
Это простой обязательный шаг, позволяющий убедиться, что ваш вклад соответствует требованиям проекта.

#### Запуск Psalm

```terminal
./vendor/bin/psalm --no-cache
```

### Сохраняйте решения простыми

При участии в разработке Spiral старайтесь делать код максимально простым и понятным. Сопровождающие предпочитают
решения, которые легко понять и реализовать, излишне сложным вариантам. Подготавливая pull request, выберите наиболее
простой способ решить поставленную задачу и изложите его понятно. Это ускорит рассмотрение изменений.

## Сообщения о проблемах

Если при работе со Spiral вы обнаружили ошибку или уязвимость безопасности, сообщите о ней. Сопровождающие серьёзно
относятся к таким обращениям и постараются устранить проблему как можно быстрее. Создайте
[issue](https://github.com/spiral/framework/issues) в GitHub-репозитории `spiral/framework`.
